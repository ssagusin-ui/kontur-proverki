# Технический аудит

По итогам повторного аудита исправлены приём неполных строк JSON, смешение действующих и исторических связей на графе, подпись частного контракта, сохранение имени проверяющего и зависимость запуска от фиксированного порта.

| Приоритет | Наблюдение | Исправление |
| --- | --- | --- |
| P0 | Семь тестов временной SQLite-базы не завершали очистку в Windows. | Тестовые соединения закрываются явно. Миграция и запись решений используют явные транзакции. |
| P1 | Некорректные типы дат и идентификаторов могли приводить к ошибкам выполнения. | Типы и интервалы проверяются при загрузке. |
| P1 | Две записи дохода могли получать одинаковый ID сигнала. | Идентификатор выводится из конкретной внешней записи. |
| P1 | Совпадение отсутствующих ID заказчика могло повысить приоритет. | Повышение требует указанного заказчика и совпадающего идентификатора. Проверяются даты участия и доступные границы семейной связи. |
| P2 | Карточка и граф требовали независимого выбора сигнала. | Добавлен прямой переход к цепочке и просмотр записей по звеньям. |
| P2 | Список общих источников HTML мог заменяться доказательствами последнего сигнала. | Таблицы источников и доказательств строятся независимо. |

Открытые ограничения: структурированный JSON, локальное хранение без ролевого доступа, синтетические сведения. Отсутствующие даты ограничивают точность. Сигнал предлагает проверить обстоятельства, а решение принимает специалист.
