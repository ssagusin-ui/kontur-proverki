# Технический аудит

По итогам повторного аудита исправлены обработка неполных записей JSON, отображение действующих и исторических связей на графе, подпись частного контракта и сохранение имени проверяющего. При запуске приложение выбирает свободный порт.

| Приоритет | Наблюдение | Исправление |
| --- | --- | --- |
| P0 | В семи тестах очистка временной базы SQLite завершалась ошибкой в Windows. | Тестовые соединения закрываются явно. Миграция и запись решений используют явные транзакции. |
| P1 | Некорректные типы дат и идентификаторов могли приводить к ошибкам выполнения. | Типы и интервалы проверяются при загрузке. |
| P1 | Две записи дохода могли получать одинаковый ID сигнала. | Идентификатор выводится из конкретной внешней записи. |
| P1 | Сравнение пустых ID заказчика могло повысить приоритет сигнала. | Повышение требует указанного заказчика и совпадающего идентификатора. Проверяются даты участия и доступные границы семейной связи. |
| P2 | Карточка и граф требовали независимого выбора сигнала. | Добавлен прямой переход к цепочке и просмотр записей по звеньям. |
| P2 | Список общих источников HTML мог заменяться доказательствами последнего сигнала. | Таблицы источников и доказательств строятся независимо. |

Текущая версия принимает структурированный JSON и хранит данные локально. Ролевой доступ не реализован. Проверки проводились на синтетических сведениях. Отсутствие дат ограничивает точность анализа. Сигнал содержит основания для проверки обстоятельств, решение принимает специалист.
