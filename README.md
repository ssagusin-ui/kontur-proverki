# Контур проверки

Рабочее место сотрудника подразделения по профилактике коррупционных правонарушений. Приложение сопоставляет декларацию с предоставленными сведениями, показывает основания сигналов и сохраняет решения. Проект подготовлен для хакатона «Код прозрачности» Президентской академии.

## Запуск на Windows

Готовая сборка для жюри находится в разделе [Releases](https://github.com/ssagusin-ui/kontur-proverki/releases/latest). Скачайте `Kontur-Windows-x64.zip` из списка файлов выпуска.

Переносимая сборка с отдельным окном. Распакуйте весь архив и дважды щёлкните **«Контур проверки.exe»**. Откроется окно приложения с собственной иконкой. Интерфейс использует системный компонент Microsoft WebView2 Runtime. Для работы с демонстрационными данными интернет не требуется.

Закройте окно обычной кнопкой в заголовке. Приложение остановит запущенный им сервер, а проверки останутся в storage/kontur.db. Если WebView2 недоступен, приложение предложит открыть рабочее место в браузере. В режиме браузера для полной остановки используйте stop_windows.cmd.

### Запасной запуск в браузере

Из исходников: установите Python 3.13 x64, выполните install_windows.cmd и запустите start_windows.cmd. Установка загружает зависимости, закреплённые в requirements.txt.

Из переносимого архива: распакуйте все файлы в доступную для записи папку и дважды щёлкните start_windows.cmd. Интерпретатор и библиотеки включены. Нужны Windows x64 и системный браузер.

Лаунчер выводит сообщение о запуске и открывает рабочее окно Microsoft Edge. При ошибке запуска Edge используется браузер по умолчанию. Сервер выбирает свободный локальный порт из диапазона 8517–8536, текущий адрес доступен в storage/address.txt. Повторный запуск из той же папки использует действующий сервер и снова открывает рабочее окно.

Для завершения закройте рабочее окно и запустите stop_windows.cmd из той же папки. Этот файл останавливает сервер конкретной копии. Данные сохраняются в storage/kontur.db. При переносе существующей базы остановите приложение и используйте копию файла. Подробности об ошибках запуска записываются в storage/server.log. Для изолированной проверки можно указать другой путь в переменной KONTUR_DB.

## Ключевой сценарий

1. Откройте «Новая проверка» и выберите «Семейная цепочка и госконтракт».
2. Запустите анализ. Откройте сигнал о государственном контракте и нажмите «Открыть связи на графе».
3. Проверьте граф на дату подписания и откройте «Основания по звеньям». Пунктир из точек обозначает неизвестный период. Сведения вне выбранной даты можно включить отдельно.
4. Вернитесь к сигналу, выберите статус «Запрошены документы» и сохраните обоснование.
5. Откройте журнал, затем скачайте HTML-отчёт и JSON-снимок в разделе «Отчёт».

Все встроенные имена и источники синтетические. Граф отображает связи внутри загруженного набора. Оценку документов и решение выполняет специалист.

## Контроль

В активном окружении из корня проекта выполните команды:

    python -m unittest discover -s tests -v
    python scripts/acceptance_check.py

Образец входного файла доступен в demo/case_3.json и в приложении. Формат входа — UTF-8 JSON, до 2 МБ. Сообщение об ошибке указывает раздел, номер записи и обязательное поле. Исправленный файл можно выбрать в том же поле. Для CSV и PDF нужен отдельный преобразователь.

## Устройство проекта

- app.py — интерфейс Streamlit.
- core/domain.py и core/rules.py — валидация и шесть правил.
- core/graph.py — атрибуты и происхождение связей.
- core/storage.py — SQLite, снимки, статусы и локальный журнал.
- core/report.py — самодостаточный HTML-отчёт.
- demo/ и tests/ — синтетические наборы и проверки.

JSON-экспорт format_version=1.0 включает run_id, created_at, case, signals, reviews, events и audit. case содержит исходный нормализованный снимок. Сигналы ссылаются на доказательные записи, reviews индексируется по ID сигнала, events отсортирован по последовательности. Контроль согласованности описан в audit.

Ограничения и архитектура описаны в docs/.
