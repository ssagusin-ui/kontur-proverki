# Контур проверки

«Контур проверки» помогает сотруднику подразделения по профилактике коррупционных правонарушений сверять декларацию с другими сведениями. По каждому сигналу специалист видит основание, может обратиться к исходной записи и сохранить своё решение. Проект подготовлен для хакатона «Код прозрачности» Президентской академии.

## Как открыть приложение на Windows x64

1. Скачайте `Kontur-Windows-x64.zip` со [страницы выпуска](https://github.com/ssagusin-ui/kontur-proverki/releases/latest).
2. Распакуйте весь архив в папку с правом записи.
3. Дважды щёлкните **«Контур проверки.exe»**. Откроется отдельное окно приложения. Адрес вводить не требуется.

Для работы окна используется системный компонент Microsoft WebView2 Runtime. Python и библиотеки входят в архив. Со встроенными наборами можно работать без интернета. Чтобы завершить работу, закройте окно приложения. Оно остановит свой локальный сервер. Проверки сохраняются в `storage/kontur.db`.

<details>
<summary>Если окно не открылось или вы запускаете проект из исходников</summary>

**Переносимая сборка.** Если окно WebView2 не открылось, воспользуйтесь кнопкой «Открыть в браузере». Запасной способ запустить тот же интерфейс — открыть `start_windows.cmd` из распакованной папки. Для этого нужен системный браузер.

**Запуск из исходников.** Установите Python 3.13 x64 и выполните `install_windows.cmd`. На этом шаге загружаются версии библиотек, указанные в `requirements.txt`. Затем запустите `start_windows.cmd`.

Командный файл выводит сообщение о запуске и открывает окно Edge. Если открыть его не удалось, используется браузер по умолчанию. Приложение выбирает свободный локальный порт в диапазоне 8517–8536 и записывает адрес в `storage/address.txt`. Повторный запуск из той же папки снова открывает интерфейс действующего сервера.

Чтобы завершить работу в браузере, закройте окно и запустите `stop_windows.cmd` из той же папки. Команда останавливает сервер только этой копии. Сведения об ошибках запуска записываются в `storage/server.log`. Перед переносом базы остановите приложение и сделайте копию `storage/kontur.db`. Путь к отдельной базе для проверки можно задать в переменной окружения `KONTUR_DB`.

## Работа с проверкой

В разделе «Новая проверка» можно загрузить свой JSON в кодировке UTF-8 размером до 2 МБ или выбрать встроенный набор, например «Семейная цепочка и госконтракт». Все имена и источники во встроенных наборах вымышлены. Образец файла доступен [в репозитории](demo/case_3.json) и в самом приложении. При ошибке обязательного поля сообщение указывает раздел, номер записи и название поля. Исправленный файл можно загрузить там же. Файлы CSV и PDF требуют предварительного преобразования.

После запуска анализа откройте интересующий сигнал. Кнопка «Открыть связи на графе» ведёт к связанным записям. Для контракта можно выбрать дату подписания и открыть «Основания по звеньям». Линия из точек обозначает неизвестный период связи. Связи вне выбранной даты можно включить отдельно. Граф строится по загруженному набору.

Решение принимает специалист. В карточке сигнала он выбирает статус, например «Запрошены документы», и сохраняет обоснование. История изменений доступна в журнале. В разделе «Отчёт» можно скачать HTML-отчёт и снимок в формате JSON.

## Формат экспорта

В версии `format_version=1.0` поля `run_id` и `created_at` содержат идентификатор и время создания проверки. В `case` хранится исходный нормализованный снимок, в `signals` — сигналы со ссылками на записи-основания. Решения в `reviews` сгруппированы по идентификаторам сигналов. События в `events` перечислены в порядке записи. В `audit` приведены результаты проверки согласованности.

## Устройство проекта

| Путь | Назначение |
| --- | --- |
| `app.py` | Интерфейс Streamlit |
| `core/domain.py`, `core/rules.py` | Проверка входных данных и шесть аналитических правил |
| `core/graph.py` | Построение связей, их атрибуты и источники |
| `core/storage.py` | Хранение снимков, решений и журнала в SQLite |
| `core/report.py` | Формирование автономного HTML-отчёта |
| `demo/`, `tests/` | Синтетические наборы и автоматические тесты |

Условия срабатывания правил и ограничения описаны в [методике](docs/METHODOLOGY.md), обработка и хранение данных — в [описании архитектуры](docs/ARCHITECTURE.md).

## Тестирование

Команды выполняются из корня проекта в окружении с установленными зависимостями.

```console
python -m unittest discover -s tests -v
python scripts/acceptance_check.py
```

Результаты приведены в [отчёте о тестировании](TEST_REPORT.md) и [отчёте о проверке окна Windows](desktop/TEST_REPORT.md).
